One place for your OpenAI, Claude, Gemini and Groq keys

If you build with AI, you probably have the same keys pasted into a dozen .env files, a bill from one provider while another's free tier sits unused, and no idea which script spent what. Here's a simpler setup.

The problem with a .env in every project

  • Keys get everywhere. Each new bot or script gets its own copy. Rotate a key and you're hunting through folders, and one of those folders ends up on GitHub.
  • Free tiers go to waste. Gemini, Groq, OpenRouter and Mistral all give you a free daily allowance. Most scripts hard-code one paid provider, so the free ones never get used.
  • A rate limit breaks the script. When the one provider you picked says "429, slow down" or "daily quota used", the script just fails.
  • You can't see who spent what. The provider's bill shows one total, not which of your projects ran it up.

Developer tools like LiteLLM fix some of this, but you have to set up and run a proxy server yourself. If you just want your keys in one place on your own PC, that's a lot of setup.

How Helmdeck handles it

1. Add each key once

Click the key icon in Helmdeck's title bar, press Add key for each provider and paste it in. Get a key opens the provider's sign-up page if you don't have one yet. Helmdeck works with:

ProviderTier
Ollama, LM Studio, or any OpenAI-compatible server on your PCFree, nothing leaves your computer
Google Gemini, Groq, OpenRouter (":free" models), MistralFree daily allowance
Anthropic Claude, OpenAI, xAI Grok, DeepSeekPaid, pay as you go

Keys are encrypted with your operating system's own protection and stay on your PC. They're only ever sent to the provider they belong to, and the app only ever shows the last four characters.

2. Your builds get them automatically

Any bot or script you add to Helmdeck can be set to "Give it my keys". When it starts, it gets the usual variables, like OPENAI_API_KEY, ANTHROPIC_API_KEY, GEMINI_API_KEY and GROQ_API_KEY, so the providers' own libraries work with no code changes and no .env file. Builds you install from other people never see your keys. They get "Gateway only" instead, which lets them use your AI without ever seeing a key.

3. Use free models first

Helmdeck runs a small OpenAI-compatible endpoint on your PC. Point any OpenAI client at it with model: "auto" and it tries models on your PC first, then free tiers, then paid keys. You can flip the first two so free tiers go first. When a provider says rate limited, quota used or out of credit, Helmdeck rests that key and sends the same request to the next one, so your script doesn't notice.

import os
from openai import OpenAI

client = OpenAI(base_url=os.environ["HELMDECK_AI_URL"],
                api_key=os.environ["HELMDECK_AI_KEY"])
reply = client.chat.completions.create(
    model="auto",
    messages=[{"role": "user", "content": "Summarise today in one line"}])
print(reply.choices[0].message.content)

Use "free" to never spend money, "local" to keep everything on your PC, or name a provider like "groq" or "openai/gpt-5". Claude works through the same endpoint, because Helmdeck translates the request for Anthropic's API.

4. Never get a surprise bill

"Use paid keys when the free ones run out" is a switch. Leave it off and Helmdeck stops at the free limits. Helmdeck also tracks what each build spends each month, and with Pro you can set a monthly budget that stops paid keys once it's reached while free and local models keep working.

Common questions

Is it safe to keep all my keys in one app?

Safer than a dozen plain-text .env files. Keys are encrypted with your operating system's protection, stored only on your PC, and never sent anywhere except the provider they belong to.

Do I have to change my code?

No. If your code reads OPENAI_API_KEY or similar, it keeps working. You only change it if you want the free-first fallback, which is two lines.
