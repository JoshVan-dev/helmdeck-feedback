Works with Claude

Helmdeck for Claude Code and Claude Desktop

You ask Claude to build something, it works, and then it's one more folder you'll forget how to start. With Helmdeck connected, Claude puts each app it builds on your deck, starts it, and reads its output when something breaks.

Claude builds it, Helmdeck runs it

Helmdeck comes with a connector (an MCP server) for Claude Code and Claude Desktop. It also works with Cursor, Windsurf, VS Code and any other tool that speaks MCP. Once it's connected, you can say:

Build me a crypto price tracker and add it to Helmdeck.

Claude writes the app, adds it to Helmdeck with its own icon and start command, and can give it a live status line, like today's price or "needs you". Through the connector Claude can:

  • add an app it built, or update one it added before
  • see which builds are running and what each tile says
  • start and stop builds
  • read a build's latest output to find out why it stopped
  • wire an app to your AI keys through Helmdeck, so the app never sees the keys

It can't remove builds, read your AI keys, or touch anything else in Helmdeck. The connector only answers programs running as you on your own computer.

Set it up in one click

Open Helmdeck, go to Settings → Connect AI coding tools, and press the button for Claude Code. Helmdeck runs the claude mcp add command for you. For other tools it shows the settings to paste, with a Copy button. If Helmdeck isn't open when Claude needs it, the connector opens it.

More useful Claude chats

Helmdeck can also add tools to the Claude desktop app's chats: the Helmdeck connector, a Memory tool that remembers facts between chats, and Step-by-step thinking for harder problems. Helmdeck only changes its own entries in Claude's settings and keeps a copy of the original file. Restart Claude afterwards to see them.

Spend less on the Claude API

Builds that call Claude go through Helmdeck's AI gateway, which turns on a few savings for you:

  • Claude prompt caching, so long instructions you send again and again cost less
  • Reuse repeat answers for questions a build has already asked
  • Retry hiccups when the API has a brief error
  • Free and local first. Builds try Ollama and free tiers before paid keys, and each build has a "Can use paid keys" switch
  • A monthly budget cap on paid keys
